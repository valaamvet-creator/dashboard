# Дашборд выручки Паасо — дизайн

Дата: 11 сентября 2026. Согласовано с Виталием в диалоге (макеты — в `.superpowers/brainstorm/`).

## 1. Зачем

Виталий смотрит выручку Паасо в Google-таблице «Сводка выручки — Паасо и Водопады». Каждый раз он ищет одни и те же вещи: сегодня, 7 дней, месяцы, год — и обязательно сравнивает с прошлым годом. Нужен сайт-дашборд, который сам обновляется и показывает ровно эти цифры с процентами роста/падения и графиком.

Не заменяет таблицу — таблица остаётся как есть. Дашборд — второе окно на те же данные.

## 2. Требования (зафиксированы ответами Виталия)

| Вопрос | Решение |
|---|---|
| Кто видит | Без пароля. Адрес не публикуем, но защиты нет. Открытый GitHub-репозиторий — приемлемо (вариант A): цифры агрегированные, в репозитории нейтральные названия. |
| Устройство | Телефон и компьютер поровну — адаптивная вёрстка. |
| Свежесть | Каждые 15 минут, как таблица. |
| Детализация | Только общая цифра Паасо (день + ночь). Без разбивки по кассам. |
| Будущее | Заложить переключатель «Паасо / Водопады / Всё». Сейчас работает только Паасо; остальные — неактивные кнопки. |
| Компоновка | Вариант B «Сравнения — главное». |
| Стиль | Тёмный, «финансовый». |
| График по дням | Не нужен (будни и выходные расходятся, линия не читается). |

## 3. Что на странице (сверху вниз)

1. **Шапка**: «Выручка», время последнего обновления (`обновлено 22:50 · 11 сен`), переключатель объектов Паасо / Водопады / Всё.
2. **Плитки**: Сегодня · 7 дней · Средний день за 7 дней. У каждой — процент к прошлому году со стрелкой (▲ зелёная / ▼ красная).
3. **Три блока-сравнения**, каждый — две полосы (2026 синяя, 2025 серая), суммы и крупный процент:
   - **Месяц в моменте** — с 1-го числа по сегодня vs те же даты 2025.
   - **Прошлый месяц** — полный предыдущий месяц vs тот же месяц 2025.
   - **Год в моменте** — с 1 января по сегодня vs те же даты 2025.
4. **График по месяцам** — 12 месяцев, пары столбиков 2026/2025, под каждым месяцем процент год к году. Будущие месяцы 2026 — пусто.
5. **Подвал**: «Данные: кассы ОФД · обновляется каждые 15 мин».
6. **Плашка-предупреждение** (появляется только при проблеме): «данные не обновлялись с 22:50» — если `data.json` старше 60 минут; «данные за сегодня могут быть неполными» — если сервер пометил, что одна из касс не ответила.

Формат чисел: рубли без копеек, разряды через пробел; крупные — «20,4 млн». Проценты — целые.

## 4. Правила сравнения с прошлым годом

- **Сегодня** и **7 дней** — сравниваем с тем же **днём недели** год назад: сдвиг ровно на 364 дня (52 недели). Четверг 11.09.2026 ↔ четверг 12.09.2025. Причина: выручка сильно зависит от дня недели.
- **Месяц в моменте**, **Прошлый месяц**, **Год в моменте**, **График по месяцам** — по **календарным датам** (1–11 сентября против 1–11 сентября). На длинных отрезках дни недели усредняются.
- Процент = (2026 − 2025) / 2025. Если 2025 = 0 или данных нет — вместо процента «—».

## 5. Данные

### Источники (уже есть на сервере, `/root/.openclaw/workspace/revenue_sources/`)

| Касса | Источник | 2025 | 2026 |
|---|---|---|---|
| Городище Паасо (день) | Платформа ОФД, `paaso_day_platforma_ofd_z_2025_2026/ofd_z.csv` | есть | есть |
| Билетная касса (день) | там же | нет (появилась в 2026) | есть |
| Терминал (ночь) | ОФД.ру, `paaso_night_ofd_ru/ofd_sell.csv` + `ofd_z.csv` | **нет в рабочем наборе** — API отдаёт с 20.01.2025 (проверено 11.09.2026: 358 Z-отчётов, ~4,86 млн ₽) | есть |

**Паасо всего = дневные кассы + ночная касса**, обе за оба года. Ночная касса за 2025 догружается в рабочий набор один раз (шаг плана). Оговорка: 1–19 января 2025 ночной кассы нет — считается 0, отмечено в подвале страницы мелким текстом при показе января.

Сегодняшний день: дневные кассы — из чеков через API (как сейчас делает `sync_paaso_revenue_google_sheet.py`, функция `update_paaso_day_today_from_api`); ночная — из инкрементальной выгрузки ОФД.ру. Закрытые дни — по Z-отчётам.

### Дневной ряд — общий для таблицы и дашборда

Сегодня дневной ряд «дата → Паасо день / ночь / всего» собирается внутри `sync_paaso_revenue_google_sheet.py` и уходит только в Google-таблицу (`raw_days`). Чтобы дашборд показывал **те же цифры, что таблица**, скрипт синхронизации дополнительно сохраняет этот ряд локально:

`revenue_sources/paaso_daily_series.json` — `{"updated_at": "...", "days": {"2026-09-11": {"day": 241050, "night": 2300, "total": 243350, "complete": true}, ...}}` за 2025 и 2026.

Флаг `complete: false` ставится, если за дату не удалось получить одну из касс (правило из инструкции: не подменять «нет данных» нулём молча).

### Расчёт метрик → `data.json`

Новый скрипт `tools/revenue/build_dashboard_data.py` читает `paaso_daily_series.json` и пишет `data.json`:

```json
{
  "generated_at": "2026-09-11T22:50:39+03:00",
  "objects": {
    "p1": {
      "today":   {"date": "2026-09-11", "value": 243350, "prev_date": "2025-09-12", "prev": 276500, "pct": -12, "complete": true},
      "week7":   {"from": "2026-09-05", "to": "2026-09-11", "value": 2490000, "prev": 2710000, "pct": -8, "avg_day": 355700, "prev_avg_day": 387100},
      "mtd":     {"from": "2026-09-01", "to": "2026-09-11", "value": 2941400, "prev": 3460000, "pct": -15},
      "prev_month": {"month": "2026-08", "value": 20386600, "prev": 22700000, "pct": -10},
      "ytd":     {"from": "2026-01-01", "to": "2026-09-11", "value": 91800000, "prev": 88300000, "pct": 4},
      "months":  [{"m": 1, "cur": 5264200, "prev": 4867300, "pct": 8}, ...12 элементов...],
      "warnings": []
    }
  }
}
```

Объекты в файле — под кодами (`p1` = Паасо); понятные названия хранятся только в `index.html`. Водопады позже добавятся как `w1` без изменения формата.

Скрипт не ходит ни в какие API — только читает локальный файл. Поэтому его можно тестировать на копии данных.

### Расписание

В существующий `tools/revenue/hourly_update_paaso_revenue_summary.sh` (крон каждые 15 минут: 5, 20, 35, 50) после шага синхронизации таблицы добавляются два шага: `build_dashboard_data.py` → публикация `data.json` в GitHub. Ошибка на этих шагах не должна ломать обновление таблицы (шаги идут после и не влияют на статус таблицы, но пишут своё в лог и в `status.env`).

## 6. Публикация

- Новый публичный репозиторий GitHub `valaamvet-creator/dashboard`: `index.html`, `data.json`, `robots.txt` (запрет индексации), `.nojekyll`.
- GitHub Pages из ветки `main`. Адрес: `https://valaamvet-creator.github.io/dashboard/`. Свой домен (`dash.ruskeala.site`) — отдельно, потом, если захочется.
- Сервер: клон в `/root/dashboard-pub`, публикация по образцу `/root/sites-pub` (SSH-ключ сервера уже в GitHub). Каждые 15 минут: перезаписать `data.json` → `git commit` (автор задаётся через `GIT_AUTHOR_*`) → `git push`. Если `data.json` не изменился — коммит не делать.
- В `<head>` страницы `<meta name="robots" content="noindex, nofollow">`.
- Задержка деплоя GitHub Pages 1–2 минуты — приемлемо.

## 7. Страница `index.html`

- Один файл, без внешних библиотек. Тёмная тема (фон `#0f1419`, карточки `#161c23`, акцент `#3b82f6`, серый 2025 `#3a4654`, рост `#34d399`, падение `#f87171`). Системный шрифт, табличные цифры.
- Адаптив: на телефоне — одна колонка; от ~800px — плитки в ряд, три блока-сравнения в ряд, график на всю ширину.
- Скрипт: `fetch('data.json?t=' + Date.now())` при загрузке и каждые 5 минут, пока вкладка открыта. Заполняет цифры, рисует столбики (`div` с высотой в %), ставит стрелки и цвета, показывает плашку по правилам п. 3.6.
- Переключатель объектов: Паасо активен; Водопады / Всё — видимы, но неактивны с подсказкой «скоро».
- Если `data.json` не загрузился — страница показывает «Нет связи с данными» вместо пустых нулей.

## 8. Ошибки и защита от неверных цифр

| Ситуация | Поведение |
|---|---|
| Касса не ответила за сегодня | `complete: false` → плашка «данные за сегодня могут быть неполными»; проценты для «сегодня» всё равно показываются, но со знаком ⚠ |
| Сервер не обновил `data.json` > 60 мин | Плашка «данные не обновлялись с HH:MM» по `generated_at` |
| Нет данных 2025 за период | Процент «—», серая полоса не рисуется |
| Push в GitHub не удался | Лог + `status.env`; таблица обновляется как раньше; следующая попытка через 15 минут |

## 9. Проверка перед сдачей

1. `build_dashboard_data.py` — юнит-тесты на маленьком синтетическом ряде: сдвиг 364 дня, границы месяца/года, деление на ноль, `complete=false`, високосный февраль.
2. Контрольные суммы на реальных данных: август 2026 = **20 386 600 ₽**, сентябрь 1–11 2026 = **2 941 400 ₽**, год 2026 на 11.09 = **74 219 450 ₽** — как в Google-таблице; январь 2025 (только день) = **4 867 300 ₽** как в отчёте `paaso_revenue_2026_vs_2025_ytd.md`, плюс ночная 2025 после догрузки.
3. Страница: открыть локально с тестовым `data.json` в размерах телефона и компьютера, сверить с утверждёнными макетами; проверить плашки, подставив старый `generated_at` и `complete: false`.
4. Боевая проверка: после первого прогона крона открыть `https://valaamvet-creator.github.io/dashboard/` и сверить «сегодня» с таблицей.
